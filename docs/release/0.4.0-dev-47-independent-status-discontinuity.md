# 0.4.0-dev-47 — Independent status discontinuity

## Physical failure reproduced

Dev-46 initially appeared stable over short physical samples. The longer run
made the failure deterministic: position discontinuities and hard Ableton Link
re-anchors increased from 105/112 to 112/119 in 45 seconds on one continuously
playing CDJ-1500X long loop. The realtime MIDI lane simultaneously retained
p95 `0.1 ms`, zero late dispatches and zero saturation.

SoundSwitch therefore received a discontinuously moving Link phase even though
the CDJ transport was continuous. Its AutoLoop progress moved forwards and
backwards, which was also visible in the fixtures.

## Root cause

Dev-46 required a coherent precise-position cluster and a matching latest
`CdjStatus` beat. A normal status frame naturally describes the current beat,
so it could agree with a noisy position without proving that either timeline
had jumped. That agreement was incorrectly promoted to a new transport
generation and a hard Link re-anchor.

## Correction

- Track the absolute status timeline independently from precise positions.
- Record a status-jump candidate only when its own beat progression is
  discontinuous relative to elapsed time and effective BPM.
- Require three coherent status frames on the new timeline before that
  candidate becomes independent jump evidence. A return to the accepted old
  timeline resets the candidate.
- Accept a precise-position jump only when that evidence is no more than one
  second old and lands within one beat of the stable precise cluster.
- Require this evidence for known Hot Cues as well. They keep two precise
  confirmations; arbitrary loop/seek/beatjump candidates keep three.
- Expire unused status-jump evidence and consume it after an accepted transport
  generation.

The first local dev-47 candidate required only one discontinuous status frame.
A longer physical correlation still found three hard re-anchors while only one
CDJ loop wrap (`189 -> 65`) occurred. That candidate was rejected before
release. The packaged acceptance candidate uses the three-frame status
consensus described above.

## Acceptance

Automated provider regressions cover coherent precise consensus, independent
three-frame status consensus, reordered status, absence of status evidence,
matching recent evidence, stale evidence, wrong landing beats and the exact Hot
Cue sequence with an independent landing status timeline.

The packaged build was then run against the same physical CDJ-1500X long loop
with SoundSwitch kept in the foreground. Across three consecutive complete
wraps:

- position discontinuities advanced exactly `1 -> 2 -> 3 -> 4`;
- hard Link re-anchors advanced exactly `4 -> 5 -> 6 -> 7`;
- 6,637 exact CDJ positions were mapped;
- 37 AutoLoop MIDI pulses were emitted with p95 `0.1 ms`, zero late dispatches
  and zero saturation;
- Pro DJ Link recorded zero critical saturation and zero automatic restarts;
- SoundSwitch remained responsive at Link `155.0 BPM`, with Control One,
  Repeat AutoLoop and Bank 1 active.

The run included app foreground switching and ordinary phrase boundaries. No
extra transport generation was created. A physical Hot Cue press was not part
of this acceptance; its dual-consensus sequence remains covered by automated
provider regression.
