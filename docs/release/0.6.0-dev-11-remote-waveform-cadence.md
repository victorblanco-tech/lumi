# Lumi 0.6.0-dev-11 / Lumi Remote 0.1.0-dev-11 – waveform cadence

This development release removes two sources of iPhone Live waveform work
without changing the accepted RGB raster, fixed playhead, zoom behavior or the
macOS waveform renderer.

The cause was transport time semantics rather than image rendering. Lumi sent
the correct canonical beat but timestamped it when the Remote publisher ran,
up to one 50 ms publication interval after the exact Pro DJ Link Beat packet.
The iPhone interpolated smoothly and then received a slightly younger anchor at
each beat, which could appear as a small backwards correction.

The Pro DJ Link provider now retains the local monotonic receipt time of the
canonical position event. Remote snapshots and transport frames convert that
same instant to their wall-clock contract. Normal tempo-only updates preserve
the anchor phase; play, pause, seek, Hot Cue and track changes remain explicit
discontinuities. Jitter-prone precise-position packets still cannot steer the
canonical playback or any show-critical output lane.

The existing Core Animation renderer is also made cheaper without changing its
output: only the live Master owns a display link, only the waveform layer moves
per frame, static beatgrid/Hot Cue/playhead geometry is updated only after a
layout, track or zoom change, and the display link may use the device's native
refresh rate. Continuous network updates are consumed at the next VSync instead
of causing an additional off-cycle layer transaction.

## Safety boundary

- no macOS waveform code changed;
- no Pro DJ Link input decision, Light Plan, SoundSwitch MIDI or Ableton Link
  scheduling path changed;
- Remote remains presentation-only and cannot feed interpolated state back to
  the engine;
- the same high-resolution RGB raster and fixed 22% Master playhead remain in
  use.

## Verification

- canonical monotonic-to-Unix timestamp conversion is regression-tested;
- a tempo-only CDJ status update is proven not to reset the transport anchor;
- all engine, Pro DJ Link input and Remote protocol tests pass;
- all Lumi Remote Swift tests pass with warnings treated as errors;
- the actual iOS/UIKit app builds for Simulator and physical iPhone;
- the packaged Mac app followed a live LAN simulator through normal playback
  and a 60-second seek while keeping the 40-bar playhead fixed;
- the signed Remote build installed on aiVoon, restored its pinned-TLS session
  and kept publishing a live heartbeat to the Mac gateway;
- a 15.959-second physical-device `Animation Hitches` trace recorded no
  interaction delay over 33 ms and one 16.67 ms frame hitch. The headed test
  nevertheless exposed a periodic visual pause: the renderer was not blocked,
  but the stale-data guard exhausted a Mac timestamp in the iPhone clock
  domain. Dev-12 follows with an explicit clock-domain translation.
