# Lumi 0.4.0 release readiness

Status: **Accepted for direct unsigned Production promotion**  
Date: **2026-08-18**

## Decision

The owner explicitly accepts promotion from `0.4.0-dev-57` directly to
`0.4.0`, without an RC. Lumi has no external users yet and dev-57 received
intensive physical acceptance on the intended hardware. An RC would add a
label and separate database but would not add a distinct tester or environment
for this owner-only release.

The skipped RC is a conscious release decision, not a permanent removal of the
RC channel. Future releases can use `X.Y.Z-rc-N` when external testers, schema
migrations or broader distribution make staged acceptance valuable.

## Accepted evidence

- complete local functional, technical, security and Apple verification gates;
- RustSec audit of all 102 Rust dependencies and OSV audit of the Maven runtime
  graph with no reported vulnerability;
- physical CDJ-1500X x2 and DJM-V5 discovery and live transport;
- SoundSwitch, Control One and DMX coexistence;
- master handoff and realtime pitch/BPM propagation through isolated Ableton
  Link;
- exactly-once phrase AutoLoops after normal playback, start, Hot Cue and Beat
  Jump landings;
- stable operation while switching applications and navigating Lumi;
- player-2 join during a running player-1 show;
- supervised Pro DJ Link bridge failure and automatic two-deck rehydration;
- zero provider failures, fail-closed holds, late AutoLoop triggers or realtime
  queue saturation in the final inspected physical run;
- Production build 177 installed and launched as `co.victorblan.tech.lumi`, with
  engine `0.4.0`, protocol v1 and the existing Production library intact.

## Distribution boundary

The Production DMG is Apple Silicon-only, ad-hoc signed and not notarized. It
is appropriate for this private owner release and early source-available
testing. Paid Developer ID signing and notarization remain deferred until
broader distribution justifies them.

## Promotion

1. Merge the accepted `dev` ancestry into `main`.
2. Set every canonical product version to `0.4.0`.
3. Run all local release gates from the exact Production tree.
4. Build and inspect the Production DMG, checksum and SPDX SBOM.
5. Install and launch the Production identity without replacing Dev data.
6. Tag the immutable main commit as `v0.4.0` and publish its assets.
7. Synchronize `main` back into `dev` and start `0.5.0-dev-1` for the next
   planned capability line.
