# Lumi 0.4.0-dev-36 — USB identity and Live resolution

This development increment removes two coupled blockers found while preparing
the physical CDJ/SoundSwitch acceptance run.

## Physical USB identity

Current trusted media uses the stable macOS filesystem volume UUID as its
source ID. A source with a `usb-fs:` identity only matches that exact mounted
volume. Visible volume names remain presentation metadata and are no longer a
fallback identity for stable sources. Name matching remains available solely
to migrate the earlier `usb-volume:` and `rekordbox-device:` records.

An inspection of an already trusted volume may expose a newer volume label.
The current inspection label is presented immediately; synchronizing selected
playlists persists that label and the current database revision atomically.

## Backup USB aliases in Live

GRAY and CHRM may both contain the same Rekordbox track ID and legitimately map
it to the same canonical Lumi track. The resolver now accepts any number of
active aliases when they unanimously identify that canonical track. If even one
alias identifies a different canonical track, resolution still fails closed.

This preserves strict matching while making trusted backup media usable in
Live Decks. A USB whose current contents have not yet been synchronized remains
unavailable until the user reviews and synchronizes the relevant playlists.

## Verification

- SQLite repository suite covers shared backup aliases and conflicting aliases.
- macOS workspace tests cover exact UUID selection, stale label presentation,
  same-name stable media isolation and legacy-name migration.
- Mounted CHRM OneLibrary inspection fits the bounded local protocol.
