# Lumi `0.6.2-dev-3`: Live Phrase Type editing

## Outcome

The phrase plan editor in both Lumi for macOS and Lumi Remote now changes the
actual Lumi Phrase Type of the selected upcoming phrase. The selector uses the
configured global Phrase Type catalog, including custom distinctions such as
`BUILDUP 1A` and `BUILDUP 2A`; it no longer acts as a second phrase-instance
selector.

The selected waveform or plan block remains the target. A saved change updates
the track's persistent Lumi timeline, refreshes that phrase in the Light Plan
and keeps the other manually selected AutoLoops intact. The target phrase's old
role-specific AutoLoop override is deliberately cleared so Lumi can resolve a
compatible choice for its new Phrase Type.

Only future phrases can be changed. Active and completed phrases, protected
phrase timelines, stale plan revisions and inactive Phrase Types fail closed.

## Isolation

Phrase Type editing is a revision-bound control-plane command. It never emits a
SoundSwitch trigger by itself and does not run on, restart or block the Pro DJ
Link ingress, Ableton Link relay or exactly-once AutoLoop output lanes. Normal
phrase-boundary execution remains the only realtime lighting authority.

## Evidence

- the full Rust regression set passes, including persistent timeline reload,
  active-phrase rejection and the authenticated Remote command path;
- the real macOS client-to-engine process integration changes a future Phrase
  Type and verifies the updated plan and library revision;
- all macOS and Lumi Remote packages pass with warnings treated as errors;
- both complete app targets build successfully;
- the technical performance gate remains green, including the bounded Pro DJ
  Link ingress and engine snapshot budgets;
- the dependency-security and release-license gates pass.

This development delivery pairs Lumi `0.6.2-dev-3` with Lumi Remote
`0.1.1-dev-1`.
