# Lumi 0.6.0-dev-7 – Remote Gateway update safety

This development build makes Remote Gateway upgrades explicit and completes
the first headed Mac-to-iPhone Simulator acceptance path.

## Fixed

- Lumi validates the gateway `productVersion` before accepting its local
  service record. An older helper can no longer be shown as Ready.
- Enabling iPhone Remote with an obsolete helper unregisters and registers the
  helper bundled with the current app. If macOS requires renewed Background
  Item approval, Lumi reports that requirement instead of silently polling.
- The gateway advertises its ephemeral TLS port in its release-scoped Bonjour
  TXT record. The iOS Simulator uses that port through the explicit host
  loopback path; physical iPhones keep normal Bonjour routing.

## Headed evidence

- packaged Lumi reported the live engine and TLS listener as Ready;
- a fresh QR invitation reached Lumi Remote and displayed the same six digits;
- explicit Mac approval created a paired observer, followed by a deliberate
  Controller transfer;
- the phone displayed Player 1, `LUMI-SIM`, “90s Bitch”, RGB waveform, phrases,
  155 BPM and the authoritative Light Plan;
- both the portrait Master-first and landscape booth compositions rendered the
  same authoritative projection without renaming the physical Player;
- `ARM`, `START` and confirmed `OFF` reached the existing engine reducer;
- simulated playback moved the Remote transport presentation;
- terminating and relaunching Lumi Remote restored the pinned-TLS session from
  its Keychain credential without another invitation.

An ad-hoc signed, versioned Dev app can still require renewed approval from
macOS after its helper signature changes. That is a platform trust decision;
Lumi now detects and explains it instead of presenting stale readiness.
