# 0.4.0-dev-44 — Exact-position AutoLoop authority

## Problem reproduced

On a physical connected deck, Hot Cue A could land in Intro while Lumi emitted
the mapped Bridge AutoLoop. The realtime MIDI lane itself remained healthy:
bounded ingress and output queues showed no saturation and CoreMIDI dispatch
remained inside budget. The incorrect decision existed before dispatch.

A Pro DJ Link Beat callback is bar-relative. It can arrive for the new Hot Cue
position before the lower-frequency deck status has replaced the old absolute
track position. Reconstructing an absolute beat from both asynchronous facts
therefore crossed transport generations.

## Correction

- the bundled Beat Link bridge publishes modern-player `PrecisePosition`
  playback milliseconds and effective BPM;
- Lumi maps milliseconds to the exact trusted local Rekordbox beat grid;
- only this mapped position can change the connected-deck phrase or authorize
  automatic lighting;
- Beat remains timing-only and playing status can update continuous Link tempo
  without a phase re-anchor;
- precise-position discontinuities invalidate queued MIDI generations before
  evaluating the landing phrase;
- predicted Bank and AutoLoop work stays as guarded deadlines until due;
- release requires a matching generation and an exact position no older than
  250 ms, otherwise output is held fail-closed.

## Automated evidence

- Java bridge protocol compiles and packages with the Beat Link 8.0.0
  `PrecisePositionListener` API.
- Protocol fixtures strictly decode a modern-player exact-position event.
- Provider regression reproduces the Hot Cue race and proves that the stale
  Bridge phrase is never emitted before exact position maps the landing to
  Intro.
- Provider regression proves a playing pitch change updates Link tempo without
  authorizing any phrase.
- Rust Pro DJ Link, engine, macOS Live and macOS Library suites pass locally.

## Physical acceptance evidence

Player 1 (`CDJ-1500X`) played the trusted `90s Bitch - Extended Mix` library
track at 155 BPM. A direct 12-second source run processed 393 new exact
positions with an empty ingress queue while the phrase changed from index 6 to
7. A controlled Hot Cue A jump from 46.5 s to 24.8 s advanced the transport
generation and emitted only Intro's configured AutoLoop 6; the previous
phrase's AutoLoop 25 was not repeated.

A following three-minute physical output soak processed 19,620 exact position
messages and emitted all 25 scheduled MIDI pulses. It recorded zero late
dispatches, cancellations, queue saturation or Link failures. Maximum measured
CoreMIDI scheduling latency was 4.634 ms and queue depth remained zero.

The same soak exposed delayed-but-monotonic precise-position callbacks that
trailed their wall-clock projection. These are network/callback jitter, not a
seek. Discontinuity detection is therefore asymmetric: a materially backward
position or a forward position ahead of elapsed time advances the generation;
ordinary forward progress that arrives late does not re-anchor Link or
invalidate output.

The corrected packaged build then ran a 90-second source-only acceptance with
2,614 exact positions. Its discontinuity count advanced exactly once, for the
physical 98.710-second backward loop wrap, and never for receive jitter. The
final three-minute SoundSwitch output soak processed another 5,207 exact
positions and recognized exactly two physical loop wraps. It emitted 26 MIDI
events with zero late dispatches, cancellations, queue saturation or Link
failures. Maximum measured dispatch latency was 153 microseconds. SoundSwitch
remained responsive after the run; Lumi returned to Off, left Link with zero
peers and retained an empty MIDI queue.

Acceptance criteria retained for repeat runs with Player 1 or Player 2 and the
same trusted USB/library revision:

1. exact-position authority is READY in Integrations;
2. Hot Cue A lands on Intro and emits only Intro's configured Bank/AutoLoop;
3. repeated forward and backward Hot Cues never emit a phrase from the previous
   position;
4. pitch-slider changes reach Link without a backwards phase correction;
5. stale or missing exact position changes status to held and emits nothing;
6. realtime output remains unsaturated and within the 20 ms dispatch budget.
