# `0.4.0-dev-38` Live rendering and output timing

## User-visible result

- Live Decks and the Track Editor show only Hot Cue letter markers above the
  waveform, using the exact imported Rekordbox colour and position.
- The duplicate Hot Cue row is removed.
- RGB waveform, phrase and AutoLoop-plan movement use a stable presentation
  clock and no longer depend on repeated SwiftUI tree refreshes.

## UI diagnosis and correction

Sampling the connected two-deck Live view repeatedly identified
`NSHostingView.invalidateSizeConstraintsIfNecessary`, `minSize` and
`sizeThatFits` as the hot stack. Nested root `.frame(minWidth:minHeight:)`
modifiers caused a size-constraint feedback loop on macOS 26.

Lumi now sets the minimum application window size once through AppKit. The same
connected Live state changed from approximately 74–99% UI-process CPU to these
samples after the correction:

`0.0, 0.1, 0.2, 2.9, 0.3, 0.2, 0.4, 0.5, 0.5, 0.3%`

The engine remains separate from this presentation work.

> Follow-up: installed-path validation later found that the original
> `onAppear` window lookup could race `WindowGroup` creation and leave automatic
> hosting-size measurements enabled. Dev-39 moves the same policy to
> `viewDidMoveToWindow`; the Dev-38 source measurement remains historical
> evidence, not the final installed-path result.

## SoundSwitch output timing

Command:

```bash
LUMI_AUTOLOOP_SOAK_SECONDS=60 cargo test --locked --release \
  -p lumi-midi-output --test realtime_soak \
  realtime_lane_configurable_soak_retains_correctness_and_latency \
  -- --ignored --nocapture
```

Result:

| Metric | Result |
|---|---:|
| Scheduled | 2,265 |
| Emitted | 2,146 |
| Stale work deliberately cancelled | 119 |
| Saturation | 0 |
| p50 | 64 µs |
| p95 | 5.038 ms |
| p99 | 5.065 ms |
| Maximum | 5.719 ms |
| ADR budget | p95 ≤ 20 ms |

The realtime lane owns CoreMIDI deadlines on its dedicated bounded thread.
SwiftUI, waveform rendering, SQLite and USB work cannot execute on that thread.

## Remaining release evidence

This Dev evidence measures scheduling through Lumi's CoreMIDI boundary. It does
not measure SoundSwitch processing, Control One, DMX transport or lamp response.
A physical full-chain timing run remains required before `0.4.0-rc-1`.
