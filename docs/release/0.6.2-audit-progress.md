The installed development app recognized **90s Bitch — Extended Mix** on Player
1 and **My Favourite Regrets (Vic DJ Edit)** on Player 2 from the network
simulator. Existing phrases, RGB waveforms and prepared plans were visible.

follow-up and is not being marked as a successful full navigation regression.

## Follow-up: atomic Live edits

Live Phrase Type and AutoLoop edits now stage their context, plan and runtime
reduction before changing authoritative state. Timeline persistence is the final
fallible operation; SQLite rollback and optimistic revisions remain authoritative.
Failed compilation/reduction/database writes leave the show and Library unchanged,
and the same edit can be retried after recovery. A no-change AutoLoop command no
longer installs a hidden override.

No user database, installed app, waveform renderer or MIDI/Link algorithm was
changed for this verification. New tests use temporary databases, including an
actual SQLite trigger that fails after a timeline revision insert but before its
phrase rows complete. Headed acceptance and a new installable build remain pending.

Verification for this follow-up: **408 Rust tests passed**, 14 intentionally
ignored tests in the broad run. The new release-mode component benchmark was run
explicitly: 200 successful prepare/reduce/commit operations, p50 **381 µs**,
p95 **445 µs**, p99 **515 µs**, maximum **662 µs** on the small in-memory fixture.
This is not a measurement of CDJ-to-MIDI latency, SQLite contention, or a proof
that preparation has moved outside the show task. The 20 ms p95 component guard
passed. Engine Clippy and version/structure/architecture checks passed.

A fresh read-only UI sample still shows substantial SwiftUI/AppKit layout work;
the engine remains running separately. The UI timeout's cause has not been
established, so no rendering or accessibility workaround was introduced.
