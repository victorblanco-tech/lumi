## Measurements

Verification for this increment: **405 Rust tests passed**, 13 intentionally
ignored hardware/soak/performance tests in the broad run; targeted 10k and
snapshot benchmarks additionally passed. **198 Swift tests passed** through
`verify-apple-fast.sh`, which also built the actual macOS and iOS apps. Workspace
Clippy (`--all-targets --all-features -D warnings`), formatting, version,
structure and architecture checks passed. Ignored hardware tests are not being
counted as successes.

Local Apple Silicon Mac, optimized Rust build, temporary fixtures. These are
component/process measurements, not proof of physical lighting latency.

| Scenario | Observed result |
| --- | --- |
| 10,000-track import | 228.96 ms |
| Library page queries | 22.66 ms |
| Search | 6.37 ms |
| Workflow query | 8.14 ms |
| 250 full snapshots | p50 1,327 µs; p95 1,537 µs; p99 1,685 µs; max 1,730 µs |
| Live-only snapshot | p95 306 µs |
| Partial desktop authentication held open | 61 pump ticks during 300 ms; max lateness 803 µs |

The 10k benchmark is explicitly run with `--ignored --exact --nocapture`, rather
than silently selecting zero tests. Snapshot timing currently measures the
small deterministic fixture, not a large user's library under SQL contention.

## Headed observation

The installed development app recognized **90s Bitch — Extended Mix** on Player
1 and **My Favourite Regrets (Vic DJ Edit)** on Player 2 from the network
simulator. Existing phrases, RGB waveforms and prepared plans were visible.
Start/Pause transitions and a simulated Master handoff were observed. No user
phrase or MIDI mapping was edited. No physical lighting acceptance is claimed.

Navigating to Library exposed a long accessibility-tool wait and high UI CPU.
The sampled engine remained running with low CPU. This observation requires
follow-up and is not being marked as a successful full navigation regression.
