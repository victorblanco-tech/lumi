## Follow-up: atomic Live edits

Live Phrase Type and AutoLoop edits now stage their context, plan and runtime
reduction before changing authoritative state. Timeline persistence is the final
fallible operation; SQLite rollback and optimistic revisions remain authoritative.
Failed compilation/reduction/database writes leave the show and Library unchanged,
and the same edit can be retried after recovery. A no-change AutoLoop command no
longer installs a hidden override.

No user database, installed app, waveform renderer or MIDI/Link algorithm was
changed for this verification. New tests use temporary databases, including an
actual SQLite trigger that fails after a timeline revision insert but before its
phrase rows complete. Headed acceptance and a new installable build remain pending.

Verification for this follow-up: **408 Rust tests passed**, 14 intentionally
ignored tests in the broad run. The new release-mode component benchmark was run
explicitly: 200 successful prepare/reduce/commit operations, p50 **381 µs**,
p95 **445 µs**, p99 **515 µs**, maximum **662 µs** on the small in-memory fixture.
This is not a measurement of CDJ-to-MIDI latency, SQLite contention, or a proof
that preparation has moved outside the show task. The 20 ms p95 component guard
passed. Engine Clippy and version/structure/architecture checks passed.

A fresh read-only UI sample still shows substantial SwiftUI/AppKit layout work;
the engine remains running separately. The UI timeout's cause has not been
established, so no rendering or accessibility workaround was introduced.

The original 120-second combined test passed 59 pitch changes, 17 seek landings
and 10 operation cycles, with Pro DJ Link source-age p95 10 ms, p99 20 ms and no
Link failures. **Its MIDI latency result is invalid:** MIDI auto-publication was
disabled, the scheduler had no requests and no latency samples. The 28 output
records alone did not prove MIDI dispatch. Pump maximum lateness reached 83 ms;
the outstanding synchronous-work isolation is not considered solved.

The combined test now explicitly publishes MIDI and requires actual new pulses,
completed AutoLoops, emitted lane messages and non-empty latency samples before
timing can pass. A regression rejects each empty counter and stale pre-run pulse
counts. The shell gate checks exclusive ownership before using real endpoints.
Evidence schema 2 includes the dispatch and sample counts. A fresh real-MIDI run
is required; the earlier green result is not reused as proof.

The schema-2 rerun passed for 120 seconds with real CoreMIDI: **28 requested and
completed AutoLoops, 29 new pulses, 29 lane emissions and latency samples**, zero
failed/cancelled executions and zero lane saturation. MIDI lane dispatch lateness
was p50 **23 µs**, p95 **68 µs**, p99 **145 µs**, max **1,593 µs**. These are local
dispatch measurements, not CDJ-to-lamp or SoundSwitch-rendering latency. Pro DJ
Link source-age p95 was **10 ms**, p99 **20 ms**; Link had one peer and no failures.
Aggressive snapshot polling still exposed pump lateness (max **84,606 µs**), so
the synchronous-work isolation story remains open.

## Native iPhone Simulator recovery

The first installed Simulator binary repeatedly failed Keychain access with
`-34018`: the verification scripts built it with `CODE_SIGNING_ALLOWED=NO`.
Building with normal local Simulator signing and the existing app-scoped
entitlements restored the **existing pairing**, without deleting credentials,
re-pairing, changing Controller ownership or weakening storage. Apple describes
this error as a missing-entitlement failure and recommends checking the built
app's entitlements ([Apple guidance](https://developer.apple.com/forums/thread/114456)).

Both Apple build gates now sign the Simulator binary locally and inspect its
embedded Mach-O Simulator entitlements, not just the input plist. The positive
gate passed; a binary without those entitlements was correctly rejected. A paid
developer membership is not introduced by this local Simulator build.

In the native iPhone 17 Pro Simulator, both prepared Players and live waveform
playback appeared. Start selected on the Mac propagated to Remote. The existing
Simulator pairing is an **Observer**; its mutation controls correctly remained
disabled. Turning only Remote off on the Mac retained all three unavailable
status indicators on the phone, while the Mac stayed in Start/Ready with the
Master playing. Turning Remote back on recovered the existing connection and
Ready statuses automatically. Physical-iPhone and Controller mutation acceptance
are not claimed by this Observer test.

During the native test, a +4.2% simulator pitch change appeared as **161.5 BPM**
in both SoundSwitch and Lumi Remote; returning to 0% restored 155 BPM. The final
fast Apple gate passed all 198 Swift tests and both application builds, including
the new embedded-entitlements check. The earlier full 205-test run provides the
separate exclusive CoreMIDI evidence; it was not repeated concurrently with the
running app.

Original-resolution iOS evidence was captured at **1206 × 2622**, including the
two requested tracks. Mac/simulator documentation images still require native
HQ capture; compressed Computer Use images have not replaced published assets.
