# Lumi `0.4.0-dev-57` — dynamic Pro DJ Link device recovery

Dev-57 fixes the physical show case where a second CDJ is powered on while a
first player is already live.

## Fixed

- temporary no-track/no-BPM sentinel values from a warming CDJ are no longer
  emitted as valid realtime tempo;
- one joining player can no longer restart the complete Pro DJ Link bridge;
- a genuine supervised bridge restart preserves the domain source sequence
  and track-load identity allocator;
- rediscovered loaded decks are accepted by the reducer and automatically
  rehydrated instead of remaining empty until Lumi is restarted;
- the independent Ableton Link and sparse AutoLoop lanes retain their existing
  fail-closed behavior during a real source interruption.

## Regression evidence

- Java bridge tests cover invalid warm-up BPM sentinels and valid stopped/live
  deck tempo;
- Rust provider tests perform a complete fail, unload, bridge recovery and
  reload with a fresh bridge decoder sequence;
- all recovered domain observations are proven newer than the pre-failure
  source sequence and the recovered deck receives a new track-load identity;
- Pro DJ Link, engine and native application verification remain release gates.

## Installed hardware recovery evidence

The DMG-installed native app was attached to the two physical CDJ-1500X
players and DJM-V5. Both paused, library-backed tracks were visible with the
correct master, BPM and beat state. The supervised Java bridge was then
terminated once to exercise a stronger failure than a player joining the
network. The launchd engine stayed alive, failed closed, restarted the bridge
once and rehydrated both decks without restarting Lumi. The recovered source
sequence and track-load identities advanced, while queue saturation, ignored
events and provider failures remained zero. Reopening the native UI showed
both decks and a healthy Link lane again.

The exact power-on sequence reported by the user remains the final physical
acceptance action: start a show with player 1 and then power on player 2.
