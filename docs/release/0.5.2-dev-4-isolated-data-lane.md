# 0.5.2-dev-4 – Isolated data lane

USB OneLibrary work can no longer run as a command inside Lumi's realtime
engine loop. Inspection, playlist synchronization and review resolution use
the existing short-lived worker process with a hard 75-second deadline.

SQLite now has a documented and tested concurrency policy:

- WAL separates readers from the isolated writer;
- `synchronous=NORMAL` keeps committed transactions consistent without adding
  full-sync latency to ordinary library edits;
- automatic checkpoints run at 1,000 WAL pages;
- a two-second busy deadline absorbs normal commit overlap and then fails
  visibly instead of waiting forever.

A two-connection regression test holds a real write lock briefly and proves
that the second connection waits and then commits successfully within bounds.
The architecture gate prevents USB data commands from returning to the
realtime protocol.
