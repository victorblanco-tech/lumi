# Lumi 0.5.0-dev-33

This Dev release fixes the live future-phrase Theme edit that could leave the
macOS app unable to decode further engine snapshots.

## Root cause

The plan correctly changed the Theme on the selected future phrase, but its
library materialization still selected AutoLoops from the opening Theme. With a
real SoundSwitch catalog, Theme banks can expose different variants and button
numbers. The resulting snapshot could therefore contain a new Theme action and
an incompatible old-Theme resolution. The strict client decoder rejected that
inconsistent state and eventually reported that the local engine could not
start, although the launchd process itself had not exited.

## Fix

- Resolve and compile every changed cue against its own Theme/Bank.
- Preserve prior phrase choices without rerunning their variation.
- Recompile the selected phrase and all successors before accepting one atomic
  plan revision.
- Represent missing sparse-Theme coverage as a safe hold.
- Keep mixed-Theme plan evidence and provider modifiers immutable before the
  realtime phrase-boundary lane sees the revision.

## Acceptance

- Changing a future phrase to another Theme keeps the Lumi session connected.
- Earlier phrases do not change.
- Action Theme, `libraryResolution.bankNumber` and selected AutoLoop address
  agree for every mapped cue.
- The new regression uses a target Theme with only AutoLoop 32 for the selected
  phrase, preventing equal-layout fixtures from hiding the defect.
