# Lumi 0.4.0-dev-52 — SoundSwitch MIDI 1.0 compatibility

Dev-52 keeps the exactly-once phrase executor from dev-51 and corrects the
external MIDI provider boundary used by SoundSwitch.

## Included

- `Lumi Virtual MIDI` and `Lumi Clock` are classic CoreMIDI MIDI 1.0 sources;
- output uses legacy `MIDIPacketList` delivery instead of UMP event lists;
- Note On and Note Off remain one semantic pulse and are encoded as separate
  immediate MIDI packets;
- no periodic, BPM-driven, progress or seek-correction AutoLoop messages;
- version-specific promises were removed from operational UI copy;
- E5-03 scheduled offset and explicit transport epochs move to dev-53.

## Acceptance evidence required

- Rust provider/output regression tests pass without warnings;
- a CoreMIDI monitor receives the exact configured Bank and AutoLoop notes;
- SoundSwitch visibly executes both a Lumi Test Controller action and automatic
  phrase changes;
- repeated phrase changes remain consumable after app switching;
- the realtime output lane remains unsaturated and below its latency budget.

## Acceptance evidence — 2026-08-17

- a CoreMIDI consumer received separate legacy MIDI 1.0 Note On and Note Off
  packets for both manual and automatic output, including Bank note 60 and
  AutoLoop notes 64, 69, 72 and 88;
- SoundSwitch visibly selected the configured AutoLoops after a Lumi Test
  Controller action and after automatic phrase boundaries from a physical
  CDJ-1500X;
- automatic output continued while SoundSwitch was backgrounded and after Lumi
  navigated from Live to Library;
- the physical run discovered two CDJ-1500X players and one DJM-V5, processed
  12,305 Pro DJ Link events and mapped 4,691 exact CDJ positions;
- realtime output reported p95 0.1 ms, zero late deliveries, zero saturation
  and a peak queue depth of two;
- the complete locked Rust workspace test suite, the macOS live-workspace suite
  (52 tests), formatting, version, structure and architecture checks passed.

SoundSwitch's application log is not treated as consumer acknowledgement. The
acceptance check requires observable state in SoundSwitch in addition to packet
capture and Lumi diagnostics.

Dev-52 remains a development build and is not an RC.
