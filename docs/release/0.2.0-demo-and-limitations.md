# Lumi 0.2.0 development demo and known limitations

This guide exercises the Epic 2A demo-data vertical slice in the unsigned
Apple Silicon app. It needs no internet, DJ hardware, Rekordbox, SoundSwitch or
licensed music.

## Build and launch the exact app

Run the complete repository gate and open the product it built:

```bash
cd /Users/victor/Engineering/Repo/Lumi
./scripts/verify.sh
open -n /Users/victor/Engineering/Repo/Lumi/build/DerivedData/Build/Products/Debug/Lumi.app
```

The app must report the Local Lumi Engine, serialized runtime, simulator,
planner and dry-run output provider as ready.

## Library and editor walkthrough

1. Open **Library**. Confirm three license-safe demo tracks and two playlists
   appear, then search for **Horizon Lines**.
2. Open its Track Lighting Editor. The fixed dark performance canvas shows the
   bar/beatgrid above the colored waveform, colored Lumi phrases underneath,
   and the full-track overview at the bottom.
3. Use play/pause, stop, scrub, previous/next bar, volume and **Loop selected
   phrase**. These controls audition local/generated audio only and never open
   the Live output gate.
4. Select whole bars and try split, boundary move, merge, role change,
   undo/redo and revision restore. Every accepted change creates a new Lumi
   revision; gaps, overlaps, zero-length phrases and non-bar boundaries fail
   closed.
5. Open **Settings → Phrase Roles**. Rename a role and inspect its stable ID,
   usage and source-mapping profile. Archiving prevents future assignment but
   never invalidates existing timelines.
6. Open **Settings → Output Profiles**. Inspect four named SoundSwitch banks,
   32 Autoloop positions per bank and mapped/incomplete/available status. Switch
   between **Banks & Autoloops**, **Virtual Controller**, and **MIDI & POC**.
   Confirm Lumi is named as its own virtual controller and all live-send actions
   remain disabled.
7. Return to the editor and use the Theme preview. Track color supplies the
   explained initial choice; a preview override changes only that plan
   instance, not the library track template.
8. Use the deterministic source-refresh preview. Review metadata, beatgrid and
   phrase differences, then explicitly choose Keep, Rebase, Merge or Replace.
   No source change silently overwrites a Lumi revision.
9. Click **Load on Deck 2**, open **Live**, and inspect the prepared Next plan.
   It must identify the exact source track, analysis revision, Lumi timeline,
   phrase role, strategy, variant, Theme reason and logical dry-run Autoloop.
10. Select **64×**, click **Arm**, then **Start**, and click **Next Track**. The
    prepared plan becomes active atomically and emits exactly one simulated
    record at each planned phrase boundary.

Repeat the editor in Lumi Light and Dark appearances and switch Camelot/Classic
key notation. The canvas intentionally remains performance-dark while the host
chrome follows the selected appearance.

## Known limitations

- Direct Rekordbox 7 import is not certified yet. E2A-00 and E2A-02 require a
  separate macOS development account and disposable Rekordbox library; the
  production library must not be used for development.
- The deck source is the deterministic simulator. There is no live PRO DJ LINK,
  Beat Link or direct deck adapter in this milestone.
- Lighting output is logical dry-run evidence. Settings already projects the
  provider-neutral Group/Theme, Phrase Role and Variant catalog onto the built-in
  four-bank SoundSwitch surface, but concrete MIDI addresses and DMX output are
  not active yet.
- No SoundSwitch project is parsed. The next POC must prove Lumi virtual MIDI,
  parallel Control One input and visible DMX output through Control One before
  production binding is built.
- The Rust engine is still an app-scoped helper. LaunchAgent/background-service
  installation after the macOS UI exits is later scope.
- The app is unsigned and not notarized. DMG packaging, signing, notarization,
  auto-update, TestFlight and App Store distribution are later release work.
- The native iPhone companion and Windows app are not implemented.
- Demo source refresh is deterministic test data; it does not claim compatibility
  with an untested Rekordbox schema or waveform format.
- Runtime internet access is unnecessary. GitHub is used only for development,
  CI and release evidence.
