# Lumi `0.4.0-dev-48` — launchd engine and Link isolation

## Outcome

Dev-48 completes the architectural migration requested after the unstable
SoundSwitch soak. The macOS window no longer owns the engine process and the
Ableton Link adapter no longer consumes Lumi lighting-plan generations.

## Delivered

- per-channel non-root LaunchAgent registration through `SMAppService`;
- launchd KeepAlive ownership and atomic authenticated service discovery;
- embedded engine Info.plist plus package verification;
- one bounded same-start registration retry for macOS's cached launch
  constraint on locally ad-hoc-signed upgrades;
- preservation of the existing Dev SQLite database and session token;
- exact-PID UI detach/reattach without CoreMIDI endpoint churn;
- automatic UI reattachment after a launchd engine replacement;
- clock-only `LinkClockObservation` with no phrase, AutoLoop, Hot Cue, seek,
  output or lighting-operation fields;
- Link transport follows Local Playback/Pro DJ Link playback independently of
  Off, Arm, Start and Pause;
- phase commands limited to initial Link acquisition, source handover and
  stopped-to-playing;
- regression coverage proving show generation and transport-discontinuity
  metadata cannot enter the Link adapter.

## Local migration evidence

- service label: `co.victorblan.tech.lumi.dev.engine`;
- launchd state after migration: `running`, managed by Service Management;
- UI Quit/relaunch: engine PID and launchd run count unchanged;
- clean build 160 fault injection: launchd replaced engine PID `78591` with
  `78603`, incremented its run count from 1 to 2 and the still-open UI
  automatically authenticated against the replacement endpoint;
- discovery record and token permissions: owner read/write only;
- installed UI authenticated against protocol v1 and retained the existing
  65-track Dev library;
- packaged helper: Apple Silicon with embedded `__TEXT,__info_plist` section.

The disposable dirty build used to validate the migration is not a release
artifact. A clean package is rebuilt after the Dev commit so revision, build
number, SBOM and checksum describe the committed source.

## Remaining physical evidence

- login-start and Login Items approval behavior;
- long physical CDJ/SoundSwitch/Control One/DMX soak;
- dedicated Hot Cue landing acceptance for AutoLoop MIDI. Link phase is not
  used as a substitute for that show-control assertion.
