# Lumi 0.6.2-dev-6 / Remote 0.1.1-dev-3 — Controller ownership

Date: 2026-09-05. Scope: E10-07, not completion of the full Epic 10 audit.

## What changed

- A persisted Controller remains the owner while offline and through client or
  gateway restarts. Only the first pairing may select an owner automatically.
  Explicit revocation leaves no Controller until a Mac transfer is requested.
- Registry and live permissions commit together, with consistent lock order.
  Failed persistence leaves ownership, credentials, lease and history unchanged.
  Re-pairing a known device no longer erases its existing ownership flag.
- Legacy trust stores retain their pairings. Even an empty legacy store does
  not reactivate automatic selection after earlier revocations.
- A transfer during the initial authentication response cannot be missed by
  the connection's trust-change subscription.
- The Mac exposes a bounded 32-entry Control history and the reported client
  version. No credentials, pairing secrets or lease identifiers enter that
  history. Entries do not attempt to reconstruct earlier events.
- Remote distinguishes green **Connected · Controller** and **Connected · View
  only**. Tapping the title opens role, controlling-device and version details
  without changing the height of the Live controls. Old clients remain wire
  compatible; unreported metadata is not invented.
- A stopped gateway has unavailable statistics, not zero paired devices or a
  claim that its saved Controller was removed.

The earlier unexpected role transition was not reproduced or historically
attributed. These are verified corrections to concrete ownership/persistence
paths plus observability for any future report, not proof of its exact cause.

## Native UI verification

Installed Mac dev-6 and iPhone 17 Pro Simulator dev-3, retaining the existing
four pairings. The physical iPhone's 0.1.0 build 12 was not updated or re-paired.

1. Existing physical-iPhone Controller survived installation. Simulator returned
   with a green View only label, disabled show controls, visible integration
   statuses and the correct version/owner in the details popover.
2. Mac Off → Arm → Start → Pause → Off left that Observer role unchanged.
3. Explicit Make Controller for the Simulator caused reconnect and enabled its
   controls. Arm, Start and Pause commands from Remote reached the Mac.
4. Six further Mac mode changes retained Simulator Controller after every step.
5. Remote was stopped/restarted while Mac stayed in Start/Ready. Remote showed
   unavailable statuses with disabled controls, then recovered the same owner.
6. Terminating/relaunching the Simulator app recovered the Controller without
   pairing. Remote Off confirmation successfully stopped the Mac show.
7. Explicit transfer restored the original physical-iPhone Controller. The
   Simulator returned to View only. The Mac Control history contained exactly
   the two deliberate transfers, no entries from mode changes or restarts.

Native Remote evidence is stored at original 1206×2622 resolution in
`build/ControllerDev6Captures`. The role/version popover was visually inspected.
The prepared 90s Bitch and My Favourite Regrets Players were loaded and paused;
this is control-plane acceptance, not a new physical lighting timing test.
Pro DJ Link, Link, MIDI and waveform processing code was not changed.
