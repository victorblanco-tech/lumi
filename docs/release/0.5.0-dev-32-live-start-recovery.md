# Lumi 0.5.0-dev-32

This development release completes the physical start-of-set path: Live Decks
survives engine-service recovery and remains isolated from Ableton Link helper
failures while the first physical Play triggers the prepared SoundSwitch
AutoLoop.

## User-visible behavior

- Live Decks remains selected across an engine or app restart.
- Loaded paused/cued tracks and their plans are restored before Lumi reports
  Ready.
- Arm and Start do not switch the workspace to Local Playback.
- Ableton Link can report a degraded state without taking Pro DJ Link or Lumi
  Virtual MIDI down with it.
- A sparse Theme may leave later Phrase Roles unmapped. UI diagnostics show
  that gap without re-resolving the complete track or terminating the engine
  after the first successful AutoLoop trigger.

## Diagnostics

Any unrecoverable launchd-engine exit is appended to `engine-fatal.log` inside
the active Lumi channel data directory.

## Regression acceptance

- Start with a mapped opening Intro and an intentionally unmapped later Drop.
- Enter Arm, then Start, then start playback from the physical cue.
- Require exactly one opening MIDI trigger, a continuing Live engine and a
  serializable snapshot whose optional unresolved diagnostic is nonfatal.
